Why a second surface

MCP(Model Context Protocol)는 LLM 에이전트가 외부 시스템의 도구를 발견하고 호출하기 위한 표준입니다. REST가 "URL과 HTTP 메서드"를 노출한다면, MCP는 이름 · 설명 · JSON 스키마를 가진 도구를 노출합니다. 에이전트는 tools/list로 무엇을 할 수 있는지 스스로 알아내고, tools/call로 실행합니다. 그래서 이 데모에서는 사람이 쓰기 좋은 REST와, 에이전트가 쓰기 좋은 MCP를 나란히 두고 같은 SQLite DB에 붙였습니다.

claude_desktop_config.json — stdio만 지원하는 클라이언트는 mcp-remote 브리지를 씁니다.

{

      "args": [

pip install mcp 후 실행하면 도구 목록과 호출 결과를 확인할 수 있습니다.

import asyncio
from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client

URL = "{{ mcp_url }}"
HEADERS = {"{{ spec.api_key_header }}": "{{ spec.api_key }}"}

async def main():
    async with streamablehttp_client(URL, headers=HEADERS) as (read, write, _):
        async with ClientSession(read, write) as session:
            await session.initialize()
            for tool in (await session.list_tools()).tools:
                print(tool.name)
            lot = await session.call_tool("get_lot", {"lot_id": "LOT0001"})
            print(lot.structuredContent)

asyncio.run(main())

스트리머블 HTTP는 SSE로 응답하므로 Accept 헤더에 두 타입을 모두 넣어야 합니다.

# 1) 도구 목록
curl -sN {{ mcp_url }} \
  -H "{{ spec.api_key_header }}: {{ spec.api_key }}" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# 2) 로트 이력 조회
curl -sN {{ mcp_url }} \
  -H "{{ spec.api_key_header }}: {{ spec.api_key }}" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call",
       "params":{"name":"get_lot","arguments":{"lot_id":"LOT0001"}}}'

# 스키마만 빠르게 보고 싶다면 (인증 불필요)
curl -s {{ base_url }}{{ spec.spec_path }}
